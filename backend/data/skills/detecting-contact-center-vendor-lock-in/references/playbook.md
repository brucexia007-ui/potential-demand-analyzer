# 厂商锁定与竞争评估手册

## VendorLockInAssessment v1

每个维度使用 `high/medium/low/unknown`：

| 维度 | 典型证据 |
| --- | --- |
| contract_lock_in | 长合同、排他、自动续约、违约成本、独家维保 |
| technical_lock_in | 私有 CTI/PBX 协议、专用硬件、E1/线路绑定、封闭平台 |
| integration_lock_in | 大量定制 API、核心业务耦合、复杂 IVR/工单流程 |
| data_lock_in | 录音、知识、模型、配置和历史数据不可迁移或缺少开放接口 |
| operational_lock_in | 运维流程、SLA、监控和应急体系依赖现任厂商 |
| personnel_lock_in | 驻场团队、稀缺技能、业务知识和培训体系绑定 |
| recent_investment_lock_in | 近期大规模升级、扩容、验收或多年续约 |

## 在任状态

- `CONFIRMED_CURRENT`：当前合同/服务期、生产运行或双方近期材料确认。
- `LIKELY_CURRENT`：历史中标与近期线索一致，但缺少当前合同或运行证明。
- `HISTORICAL`：只能确认过去使用。
- `MULTIPLE_OR_TRANSITION`：多套系统共存或处于新旧迁移。
- `UNKNOWN`：证据不足。

## 脆弱度

`vulnerability_level` 同样使用 high/medium/low/unknown，但只依据目标企业级证据：

- 高：已确认服务失败、适用合规缺口、目标在用产品 EOL、公开重招或客户明确寻求替换。
- 中：合同临近到期、成本/接口/容量问题有可靠证据，但尚无明确替换动作。
- 低：近期升级/续约、服务稳定或客户公开认可，且没有强制触发。
- 未知：只有品牌、市场传闻或其他客户事件。

## 推荐进入方式

- 底层强锁定、上层有缺口：旁路智能化、质检、知识或数据分析。
- 接口锁定：先验证开放度，提供适配层或兼容中间件。
- 合同锁定：按明确到期日提前规划，不把观察窗口写成当前采购。
- BPO 打包锁定：围绕数据控制、平台自主和多供应商治理评估解耦。
- 多套系统共存：优先统一入口、路由、数据和运营层，避免未经验证的全量替换。

## 风险扣减

风险扣减依据锁定强度、近期投资、迁移复杂度、资格差距和反证；必须保留证据 ID。不得仅因头部厂商市场地位高就自动扣分，也不得仅因外资厂商就自动加分。
