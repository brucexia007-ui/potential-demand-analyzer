## 1. 目的与口径

本文件记录候选筛选改造前的任务耗时、候选规模和模型调用基线，并记录第一轮真实 POC 的输入样本。候选、Evidence、模型调用和报告引用不是同一概念：本轮 POC 使用的是已落库 Evidence 的脱敏快照，不能代表完整搜索召回集。

所有耗时均为墙钟或 Provider 调用延迟；费用仅在存在可信的模型单价及实际 Usage 时统计。未知费用必须保持 `unknown`，不得按 0 处理。

## 2. 当前任务基线

分析任务：`0170494a-c65b-49c0-8594-b8a10e522a85`，标准售前研究，共四个维度。

| 指标 | 当前观测 | 结论 |
| --- | ---: | --- |
| 首维度候选数 | 65 | 搜索召回没有进入筛选漏斗 |
| 首维度 Evidence 数 | 65 | 候选几乎全部直接转成 Evidence |
| 首维度抽样模型调用 | 63 次 | 基本等价于逐候选调用 |

| 首维度耗时 | 27 分 18 秒 | 尚未包含其余维度、报告和审计 |
| 首维度 Token | 112,770 | 超过既有单维度 50,000 Token 配置上限 |

历史任务还观察到重复 Evidence、长任务被重投和任务状态被内外层重复更新等问题；这些问题分别由后续 WBS 的候选规范化、持久状态机、工作单元和预算账本处理。本阶段只验证筛选策略是否具备进入实现阶段的质量基础。

## 4. 基线结论

1. 旧链路的主要成本来自“候选数直接乘以单候选模型调用”，而不是仅靠增加 Worker 可以解决。
2. 首轮 POC 样本已具备真实候选和引用关系，但规模、标注来源和多样性尚不足以作为单独发布依据。
3. 第一轮真实 POC 结果详见 [筛选 POC 与 G1 决策](TASK_EXECUTION_SCREENING_POC.md)，当前 G1 为不通过。

## 5. 后续基线补全要求

- 至少补充 3 个经业务确认的历史任务样本，覆盖不同 Skill 与来源分布。
- 每个样本使用单维度 65～80 条候选；不足时标记为小样本，不混入完整长列表结论。
- 对关键引用进行人工复核，明确 `critical` 与普通金标。
- 每次 POC 同时保存 Fixture 哈希、Prompt 版本、模型/Provider、调用上限、实际 Token、费用和原始结果文件路径。
