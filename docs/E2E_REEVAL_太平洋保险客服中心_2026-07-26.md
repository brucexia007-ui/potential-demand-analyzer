## 4. 本轮新发现问题

| # | 严重度 | 问题 |
|---|---|---|
| N1 | **P1** | **日期提取成为 0 准入的瓶颈**：未知日期占比 75% → 日期门槛 → 报告级准入 0 条。基线轮能列出的 3 条历史线索（2018 话务平台/2019 客服机器人/2025 系统升级，URL 里都有日期）本轮全部消失 |

| N3 | **P2** | 「准入率 12.5%」与「报告准入 0 条」两个口径并列出现，容易误读（前者是维度级，后者是报告级），需在报告中说明 |
| N4 | **P2** | 证据列表可见近似重复（慧择保险网同一内容 ×3），但报告自述「去重 0 条」——去重逻辑未覆盖近重复 |
| N5 | **P2** | 任务失败时 `error_message` 仍为 null（本轮两次 FAILED 复现），失败原因（提取计划空批次、评估契约错误）不透传，用户看到任务死得不明不白 |
| N6 | **P2** | **DNS rebinding 守卫不兼容 fake-ip 代理环境**：`resolve_all_and_validate` 用 `is_global` 判定，Clash fake-ip（198.18.0.0/15）全量误杀；且 `SECURITY_OUTBOUND_CHECK_ENABLED=false` 在 [fetch_client.py:36-48](../backend/app/tools/fetch_client.py#L36-L48) 中只记日志不跳过校验（开关无效）。中国开发环境 fake-ip 极常见，建议支持 `SECURITY_OUTBOUND_ALLOW_CIDRS` 白名单或检测代理环境跳过 DNS 私网检查 |
| N7 | **P3** | 博查限流（429）在本轮出现 1 次，有降级处理但建议观察配额 |
