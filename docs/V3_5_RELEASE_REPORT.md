## 1. 本版达成的业务闭环

v3.5 已把平台从“完成研究报告”推进到“持续经营研究资产”：

1. 外部 Codex/Claude 风格 Skill 只能从固定 GitHub Commit 或受限离线包进入；经过静态检查、一次性标准化转换、Diff、零副作用 Mock 和人工确认后，只创建本地草稿。
2. 已确认目标企业可建立客户雷达；到期检查使用耐久任务、事务 Outbox、增量边界、Evidence 指纹去重与 Claim 变化检测。
3. 无新增 Evidence 时任务以无变化终态结束，不创建 ContextSnapshot、OIG、Gate 或 Report；有实质变化时产生新裁决，历史报告保持只读。
4. 销售可记录信号接受/拒绝、客户验证、阶段推进、Won/Lost、暂无机会和主体误判，反馈进入不可变审计账本。
5. Dashboard 以研究任务创建时间定义队列，展示累计 OIG 过门、商机推进、确认金额、调用成本、阶段停留和误判结果。
6. 校准作业输出概率曲线和改进建议；所有建议必须人工评审，不在线修改权重或生产 Skill。

## 2. 关键口径

- G1～G5 是递进门槛：G5 客户同时计入 G1～G4；每个客户只读取最新裁决。
- GX 是独立“不建议推进”终态，不参与递进过门率。
- 商机金额只读取 `CUSTOMER_CONFIRMED` 与 `CRM_IMPORTED`，不同币种不合并。
- 人工研究基线不存在时，节省工时返回 `NOT_CONFIGURED`，不由 AI 推算。
- Dashboard 只输出聚合数值，不输出客户私有文件名、存储引用、授权范围或反馈原文。
- 反馈和校准不修改历史报告、生产 Skill、推荐权重或 OIG 阈值。

## 4. 安全结论

- 外部 Skill 中脚本代码、秘密读取或外发指令均为阻断项；Mock 的网络、模型和文件写入必须为 0。
- 雷达订阅、检查运行、反馈和 Dashboard 均按当前 Workspace 查询；跨 Workspace 对象返回 404/拒绝。
- 客户私有材料不进入经营聚合响应。
- Skill 导入来源 Commit 与生成的本地版本精确绑定；上游更新不得覆盖本地修改和历史版本。
- 真实外部调用仍受数据域、模型路由、外发和预算审计边界约束。

## 5. 本轮发现并修复的问题

1. OIG 漏斗最初按最终等级分别计数，导致 G5 未计入 G1～G4。先增加失败断言，再改为“每客户最新裁决 + 累计过门”。
2. `SkillVersion.version_id` 被错误声明为自关联字段，而 001 实际要求该字段属于 `SkillImportSource`。由数据库失败复现后修正 ORM，并回归导入服务。
3. v3.3 清理器漏导入产品匹配快照模型，且批量删除未同步 identity map。分别由 teardown/清理测试复现后修正。
4. 绿地 Schema 测试错误地比较字符串与 `Column` 对象。统一改为 `table.c.keys()`，动态 Alembic 往返进一步证明无漂移。
5. Playwright 的 Commit SHA 定位器命中文案和输入框两个元素。限定为精确 textbox 后，全旅程通过。
6. pytest 9 将参数名 `request` 识别为保留夹具名，导致全量收集失败；参数改为业务语义名并增加全量收集门禁。
7. Provider 可选模型数组曾把 Python `None` 写成 JSONB `null`，与数组约束冲突；创建契约统一写数组，ORM 明确 `none_as_null=True`。
8. 自动发现测试先切换研究模式再绑定能力档案，autoflush 暴露非法中间态；测试改为一次 flush 两个字段，数据库硬约束保持不变。
9. 澄清恢复错误引用不存在的 `ClarificationResponse.created_at`；改为真实 `responded_at + id` 确定性排序，并回归预检恢复。
10. E2E 依赖旧模板 UI、固定 3001 端口和数据库残留任务；旧 UI 用例退出，认证 origin 动态化，历史/详情改为页面级确定性 Mock。

预防措施：Schema 测试统一比较字段名；组合 fixture 必测 teardown；递进漏斗必须覆盖高等级向低等级累计；浏览器定位优先角色与精确名称。

## 6. 迁移与回退策略

项目尚未正式生产上线，因此只维护最终绿地 `001`，不提供历史迁移、双读、双写或兼容分支。

- 首次产生正式业务数据前：允许在维护窗口内对空库执行 `downgrade base` 后重新 `upgrade head`。
- 首次产生正式业务数据后：不得用破坏性 downgrade 回退；必须以部署前 PostgreSQL 备份恢复为数据回退手段，并从 002 开始记录真实 Schema 变化。
- 功能级止损：可暂停雷达调度、停止 Skill 导入入口和 Dashboard 访问，但不得删除历史证据、报告、裁决或反馈账本。

## 7. 已知非阻断事项

- 现有代码仍有 Pydantic v2 旧式 `Config` 弃用警告，以及 `model_calls` 保护命名空间警告；当前不影响本轮行为，但应在后续质量清理中消除。
- Dashboard 已进入桌面与移动端共用主导航，路由与鉴权行为已纳入生产构建。
- 工时节省、商机金额和概率校准只有在真实人工基线与足够反馈样本形成后才具备业务解释力。

## 8. 正式决定

本版可作为工程发布候选进入受控业务试点评审；不得直接生产上线。解除业务 `NO-GO` 仍至少需要：

1. 20～50 家获授权真实目标企业，两名独立专家完成隐藏答案盲评；
2. 真实 GitHub 固定 Commit 导入安全与许可证复核；
3. 真实 Provider 下的 P50/P90、Token、费用、失败恢复与人工工时归档；
4. 阻断级误提升、Workspace/私有数据泄露、自动改 Skill/权重均为 0；
5. 《售前商机作战试点评分标准》全部阻断门和质量门通过。
