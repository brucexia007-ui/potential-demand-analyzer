# v3.4～v3.5 售前商机作战与持续经营试点评分标准

| 文档项 | 内容 |
| --- | --- |
| 文档版本 | v1.1 |
| 冻结日期 | 2026-07-22 |
| 适用范围 | v3.4 自动线索发现、商机假设、资格、行动、正式商机与业务输出；v3.5 Skill 导入、客户雷达、反馈、Dashboard 与校准 |
| 最小样本 | 20 家；建议 20～50 家获授权真实目标企业 |

## 1. 评测原则

1. 评测企业、我方产品档案和分析截止日期在运行前冻结。
2. 两名独立售前/行业专家先形成人工基准，答案对被评模型隐藏。
3. 专家分别打分后再处理分歧；不得由单一开发者同时充当答案制定者和裁决者。
4. 区分需求信号、推断、客户确认和正式事实；公开证据不能冒充客户确认。
5. 客户公开事实、客户私有证据和我方内部知识使用独立证据域和权限策略。
6. “暂无明确机会”是合法结论；禁止为了命中产品而反向创造客户需求。
7. 记录模型、Skill 版本、产品版本、上下文快照、调用、Token、费用、时延和人工复核时间。

## 2. 单企业评分卡（100 分）

| 维度 | 分值 | 满分条件 | 阻断错误 |
| --- | ---: | --- | --- |
| 企业主体与消歧 | 10 | 主体唯一，官网/信用代码/股票代码等可选字段使用正确 | 同名错绑、跨 Workspace 绑定 |
| Claim 与证据 | 20 | 原子结论、支持/反证、时效、真实性状态和引用均正确 | 伪造事实、引用不支持结论 |
| OIG 商机判断 | 20 | G0～G5/GX、生命周期、硬阻断和反证符合人工基准 | 将 GX/G1～G3 提升为正式候选 |
| 产品匹配 | 15 | 需求先于产品；硬门槛、能力适配、缺口和不可承诺项正确 | 忽略资质/区域/能力硬阻断 |
| 商机资格与阶段 | 10 | 信号、假设、销售接受、客户验证、正式商机严格分开 | 未经客户验证或 PASS 资格卡创建正式商机 |
| 决策链与行动 | 10 | 角色真实性、下一验证动作、问题、负责人和日期可执行 | 把公开推断写成客户确认 |
| 竞争与价值 | 10 | 覆盖现状/延期/不投资，价值假设展示来源、缺口和敏感性 | 编造 ROI、隐藏关键假设 |
| 安全与业务输出 | 5 | 私有/内部原文不泄露，Webhook 经预览确认且签名幂等 | 越权、私有材料外发、无确认发送 |

出现任一阻断错误时，该企业总分上限为 59，并计入阻断级误判。

## 3. 专家标签

每家企业至少标注：

- 人工裁决：`NO_SIGNAL / G1 / G2 / G3 / G4 / G5 / GX`。
- 是否值得销售验证：`YES / NO / UNCERTAIN`。
- 客户是否已确认：`NO / PARTIAL / YES`。
- 是否满足正式商机门槛：`NO / YES`。
- 主要硬阻断、支持 Claim、反向 Claim、候选产品和不适用产品。
- 1～3 个下一步验证动作，以及预期目标角色。
- 引用正确性、时效性和证据域。
- 专家置信度与分歧原因。

## 4. 试点门槛

### 4.1 阻断门

- 阻断级误提升：`0`。
- 跨 Workspace 或客户私有/内部原文泄露：`0`。
- 未确认 Webhook 发送或幂等重放：`0`。
- 编造确定性 ROI、预算、决策人或客户确认事实：`0`。

### 4.2 质量门

- 关键结论引用覆盖率：`100%`。
- 引用正确率：`≥95%`。
- 主体消歧准确率：`≥98%`，其余必须进入人工消歧而非猜测。
- G4/G5 与“暂无机会”宏平均 F1：`≥0.80`。
- 无机会判断准确率：`≥85%`。
- 产品硬门槛召回率：`100%`。
- 双专家单企业总分平均：`≥80/100`，且低于 70 分的企业占比 `≤10%`。

### 4.3 效率与可用性门

- 从输入企业到首个可行动结论的 P50：`≤30 分钟`；P90 在试点前冻结具体阈值。
- 相比人工基线的研究工时节省：`≥50%`。
- 计划外失败率：`≤5%`；失败必须可恢复或明确终止。
- 销售对商机假设的接受率、客户验证通过率和 30 天阶段推进率只做漏斗观测；首轮不以抬高命中率为优化目标。

## 5. 继续、修正与停止规则

- `GO`：阻断门全部通过，质量门全部通过，效率门无重大回退。
- `CONDITIONAL GO`：阻断门通过，仅有可定位的非安全质量/效率缺口，且有明确修复与复测范围。
- `NO-GO`：任一阻断门失败、样本不足 20 家、专家不独立、答案未隐藏，或无法重放证据链。
- 连续出现同一根因的阻断错误时立即暂停扩样，先修复并重跑已受影响样本。

## 6. 最小归档包

- 脱敏样本清单及授权记录。
- 人工基准、两名专家原始评分和分歧裁决。
- 每次运行的 Task/Run、Skill/产品版本、ContextSnapshot、GateDecision、Claim 和输出版本。
- Token、费用、P50/P90、失败/恢复与人工工时。
- 商机假设接受、客户验证、阶段推进、赢单/丢单或停止原因。
- 所有阻断错误、修复提交、复现测试和复测结果。

## 7. v3.5 持续经营专项门

### 7.1 Skill 导入

- GitHub 来源必须固定 40 位 Commit；分支、标签或浮动默认分支不可进入预览。
- 脚本、二进制、路径穿越、软链接、压缩炸弹、秘密读取/外发提示任一命中时，导入阻断率为 `100%`。
- 每个可导入样本必须归档许可证结论、原始快照哈希、转换结果、完整 Diff、Mock 结果和人工确认人。
- Mock 网络调用、模型调用、文件写入均必须为 `0`；导入后只能创建本地草稿，不能自动发布。

### 7.2 客户雷达与增量研究

- 仅主体状态为 `CONFIRMED` 的客户可订阅；主体误判进入单独反馈，不得静默改绑。
- 无新增 Evidence 的运行不得创建新 ContextSnapshot、GateDecision 或 Report，重复副作用为 `0`。
- 新 Evidence 去重准确率 `≥99%`；Claim 状态变化、采购、政策和合同窗口黄金样本召回率 `≥95%`。
- 雷达每轮实际外部调用、Token、费用、P50/P90 和失败状态必须可审计。

### 7.3 反馈、经营漏斗与校准

- 反馈对象、原因、有效时间和提交人完整率 `100%`；Workspace 越权成功数为 `0`。
- Dashboard 与人工 SQL 抽样口径一致率 `100%`；G5 必须累计进入 G1～G4，GX 不参与递进过门率。
- 未确认金额被计入管道金额的数量为 `0`；不同币种错误合计数量为 `0`。
- 没有人工基线时虚构节省工时的数量为 `0`。
- 校准曲线最少积累 20 个销售接受结果和 20 个客户验证结果后才允许提出阈值调整建议；每个关键概率桶建议至少 5 个样本。
- 任何反馈触发线上自动改权重、生产 Skill 或历史报告的次数为 `0`；改进只能进入新草稿和黄金用例评审。

### 7.4 v3.5 继续/停止规则

- `GO`：7.1～7.3 全部门通过，且原 v3.4 阻断门仍全部通过。
- `CONDITIONAL GO`：仅存在可定位的非安全可用性缺口，关闭雷达自动调度或 Skill 导入后仍可安全试点。
- `NO-GO`：真实样本不足、任一数据泄露、外部代码被执行、增量运行覆盖历史、未确认金额入账或校准自动更新线上配置。
