# B2B 客服中心商机决策报告模板

## 使用原则

- 先给决策，再给分析，最后给证据。
- 每个结论回答“所以是否值得投入、以什么方式投入、什么条件下停止”。
- 外部证据使用 `E` 编号；系统推断使用 `I` 编号；待验证假设使用 `H` 编号；反驳使用 `R` 编号。四类对象不得混编。
- 正文只引用与判断直接相关的少量证据；完整外部证据仅在附录出现一次。
- 章节没有足够数据时，输出“当前不可判断 + 缺失字段 + 验证方法”，禁止用通用段落填充。

## 1. 执行摘要（BLUF）

必须在首屏给出：

1. 一句话结论。
2. OIG 等级与销售投入等级（A/B/C/D）。
3. 本周唯一行动项。
4. 三个以内支撑判断及各自置信度、关键证据。
5. 结论成立所依赖的关键前提。
6. 对结论杀伤力最大的风险。

销售投入等级：

- A：已有明确采购或高确定性窗口，可以投入售前资源。
- B：存在目标企业级缺口和触发，完成指定验证后投入。
- C：只有历史基线、弱信号或证据不足，只做低成本跟踪。
- D：存在决定性反证或硬阻断，本周期放弃。

## 2. 现状判断（As-Is）

使用不同分析对象，禁止复制同一证据列表：

- 能力地图：能力、生产状态、成熟度、覆盖范围、依据和未知项。
- 在任厂商与合同：厂商、产品、合同/维保期限、锁定因素、证据状态。
- Buying Center：只列角色与验证策略；无直接证据时不得臆测具体姓名、态度或权力。
- 建设时间轴：只纳入有事件日期的目标企业事实；推算换代窗口必须显式展示依据和替代解释。

## 3. 缺口与痛点分析（Gap Analysis）

- 痛点表必须包含量化指标、样本范围、数据来源和可用性。
- 单条投诉只作为方向锚点，不能证明系统性问题。
- 行业基准必须标明年份、口径与来源；缺失时给出待补字段，不填示例值。
- 触发事件按证据强度与时间窗口排序。
- 痛点—产品矩阵每行必须绑定外部证据或客户私有材料；仅由系统推断产生的缺口不得进入“已验证痛点”。

## 4. 商机评估（Opportunity Sizing）

- 假设—置信度矩阵列出证实和证伪路径。
- 商机规模优先引用目标企业预算、中标价或可比同业项目；数据不足时输出测算公式和待补参数，不输出金额。
- 竞争态势区分在任事实、潜在竞争者和未知项；不得把行业常见厂商写成目标企业在任厂商。
- 给出全量替换、旁路增量、扩容升级、维保续约或 BPO 解耦的建议形态与进入条件。
- 评分卡使用 5/3/1 分锚点；没有数据的维度记为“未评分”，不得用默认中间分补齐。

## 5. 反证与红队检验

- 至少列出三个最强反驳；每个反驳写明杀伤力、验证路径和对当前结论的影响。
- Kill Criteria 必须可以被销售直接执行，例如“已完成同类整体升级”“未来两年无预算”“长期单一来源且无旁路入口”。
- 有直接反证时引用外部证据；没有时明确标为待验证反驳，不伪造反证。

## 6. 决策建议与行动路径

- 按“立即做、条件触发做、不做”组织资源投入。
- 验证计划必须包含待验证项、方法、建议责任角色、时限和关联假设。
- 问诊问题按业务、IT、采购角色分组，并指向 H/I/R 编号。
- 给出 30 天、60 天和事件触发式复核节点。

## 7. 附录

### 外部证据索引

- 只收录外部或客户私有原始材料。
- 每条包含编号、标题、来源等级、日期、用途和链接。
- 超过有效期的材料标记“历史背景”，不得参与当前窗口判断。

### 推断登记册

- 每条包含 I 编号、推断、外部证据链、置信度、替代解释和验证动作。
- `urn:skill-evaluation:*` 只能标识推断生成器，不得作为证据来源。

### 数据缺口声明

列出影响结论的缺失字段及其对应验证计划。说明“未发现公开证据”既不等于能力不存在，也不等于商机存在。
