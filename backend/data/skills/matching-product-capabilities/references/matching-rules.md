# 产品适配判断规则

## 1. 固定证据边界

- `[external]` 和 `[customer-private]` 只用于证明目标客户的需求、现状、缺口、约束和确认信息。
- `[internal]` 只用于证明我方产品、方案、案例、资质、区域和交付能力。
- 内部产品材料不能证明客户有需求；产品越强也不能提高客户需求证据强度。
- 行业通用痛点不能自动写成目标客户缺口；必须保留为待验证假设。

## 2. 输入要求

- 需求输入必须关联 Claim 或可审计 Evidence，并保留支持、反向、冲突、时效和确认状态。
- 只读取当前 Workspace、当前能力档案中状态为 `ACTIVE` 且处于有效期内的产品版本。
- 目标行业、地区、强制资质和交付约束缺失时，不得假设为“满足”；将其列入 `missing_information`。
- 同一需求的转载或重复切片只计一次，不得重复提高覆盖率或置信度。

## 3. 先执行硬门槛

任一候选产品命中以下条件时，先排除该产品，不进入加权评分：

1. 命中禁止服务行业或禁止交付地区。
2. 目标行业或地区明确不在产品支持范围。
3. 缺少客户明确要求的强制资质、许可证或安全认证，或资质已过期。
4. 产品能力边界、不适用场景或交付模式与已确认需求冲突。
5. 无法满足明确的数据驻留、安全、部署、接口或时间窗口要求。

全部候选均被排除时，返回 `hard_blocker=true`，列出逐产品阻断依据；高分、案例或品牌优势不能抵消硬阻断。

## 4. 再计算推荐与置信度

- 仅对通过硬门槛的候选评分。
- 默认权重：需求覆盖 55%、行业适配 15%、区域交付 15%、能力资料完整度 15%。
- `fit_verified=true` 至少要求：没有未覆盖需求、推荐分不低于 60、置信度不低于 0.60，并且没有硬阻断。
- 推荐分与置信度分开显示；资料不完整时可以有较高推荐分，但不得伪装成高置信结论。
- 同时输出信息完整度、主要正负因素、未覆盖需求和最可能改变结论的缺失字段。

## 5. 特殊裁决

- 没有客户需求输入：`fit_verified=false`、`hard_blocker=false`，输出“缺少已证实客户需求”，不得推荐产品。
- 没有有效能力档案或已启用产品：`fit_verified=false`、`hard_blocker=true`。
- 只有部分需求被覆盖：保留候选产品，但 `fit_verified=false`，输出未覆盖缺口和验证/补齐行动。
- 产品适配只决定 ProductFitGate。只有 OIG 其他前置 Gate 同时通过时，系统才可能形成 G5；产品适配不能覆盖时间窗口、客户能力基线或反证裁决。

## 6. 输出审计

- 每个需求引用外部或客户私有 Claim/Evidence ID。
- 每项产品能力、资质和限制引用内部对象 ID、版本和有效期。
- 每个阻断项说明命中的字段、规则和来源，不输出无法复核的笼统判断。
- 任何推断均标记为待验证，并生成下一步验证问题；不得编造 ROI、预算或客户确认。
