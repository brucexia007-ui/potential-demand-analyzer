# 证据与裁决规范

## 证据记录

每条证据至少保存：`evidence_id`、标题、URL 或内部来源标识、来源类型、发布者、发布时间、事件时间、抓取时间、主体范围、原文摘录、支持的声明、是否为反证。

## 来源优先级

1. 目标企业、采购人、监管机构和政府采购平台的一手材料。
2. 中标、合同、验收、审计、判决等可核验记录。
3. 供应商案例、权威媒体和行业机构材料。
4. 招聘、应用商店、投诉平台、论坛和社交媒体。

低优先级来源可以发现线索，但不得单独确认核心部署、在任厂商、当前预算或采购窗口。

## 声明门槛

| 声明 | 最低证据门槛 |
| --- | --- |
| 存在客服中心 | 目标企业一手渠道，或两条独立可靠来源 |
| 某能力已生产上线 | 明确上线/验收/运行材料；中标本身不够 |
| 某厂商为现任供应商 | 合同/中标并有当前服务期，或目标企业与供应商双方可交叉印证 |
| 已完成信创改造 | 明确指向客服系统、适配栈、范围和部署阶段 |
| 已深度智能化 | 除产品名称外，还需覆盖范围、生产状态或量化运营证据 |
| 当前采购 | 有效期内采购公告、采购意向、RFI、方案征集或明确内部材料 |
| 合同将到期 | 明确服务结束日，或可复核的合同期限推算 |
| 服务体验存在系统性问题 | 多条独立同类反馈、官方回应、监管材料或可复现实测 |
| 现任厂商易被替换 | 目标企业级合同、技术、运营或服务风险证据；不得使用品牌先验 |

## 事实、推断与未知

- `FACT`：来源明确表达，且主体、时间和范围一致。
- `INFERENCE`：由多个事实推导；必须写出推导链和替代解释。
- `UNKNOWN`：缺少证据、证据冲突或范围不清；不得补写成否定事实。
- `COUNTER_EVIDENCE`：直接削弱或限制结论的证据，例如近期续约、刚完成升级、满意度改善。

## 去重与冲突

- 同一公告被多个聚合站转载只算一个来源。
- 同一媒体集团的转载不视为独立来源。
- 新旧材料冲突时，先判断是否为不同分支、业务线、阶段或部署范围。
- 无法消解的冲突同时保留，降低置信度并生成验证问题。

## 反证搜索

对每个 G3 及以上候选至少执行一次定向反证搜索，例如：

- 是否刚完成上线、扩容或续约？
- 是否已有国产化适配或智能化能力？
- 是否为集团其他主体采购？
- 是否有官方回应说明问题已经解决？
- 是否存在长期单一来源、深度定制或迁移障碍？

反证质量比固定比例重要，不设置“必须有 20% 反证”等机械指标。

## 置信与完整性

- `confidence` 反映证据支持强度、来源质量、一致性和时效。
- `information_completeness` 反映必要字段被填充的程度。
- 二者均不等于成交概率；没有经过历史样本校准时不得输出精确赢率。
