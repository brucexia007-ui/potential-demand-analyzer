## 4. 问题清单（按严重度）

### P0 阻塞

1. **任务详情页无轮询，状态永远停留在页面打开瞬间**
   - 现象：任务执行 30 分钟，页面全程「queued / 0% / 等待中」，API 同期显示 RUNNING / 92%
   - 根因：[page.tsx:125-140](frontend/src/app/tasks/[id]/page.tsx#L125-L140) 仅在挂载时拉取一次任务详情；`lastSequence` 变化只刷新 execution 视图（[page.tsx:142-144](frontend/src/app/tasks/[id]/page.tsx#L142-L144)），从不重取 `task`；SSE 事件流在该环境疑似也未推进（30 分钟无任何更新）
2. **阻塞型澄清因此不可见，任务无限期假死**
   - 澄清面板刷新同样只依赖 `lastSequence`（[clarification-card.tsx:208-211](frontend/src/app/components/clarification-card.tsx#L208-L211)）；挂载之后产生的澄清永远不会出现
   - 叠加效应：用户侧看到的是「任务在跑但永远跑不完」，API 状态 RUNNING 与实际 PAUSED/WAITING_FOR_INPUT 语义不一致

### P1 严重

3. **主体确认澄清出现在 PRE_REPORT 阶段，时机过晚**：研究全部做完（28.7 万 Token 已花）才问「研究对象是否正确」；若用户否认，全部研究作废。主体确认应前置到 PRE_EXECUTION（`resolving-target-company` 是第一个维度，却未在那时触发确认）
4. **暂停时 `current_stage` 回退显示「准备执行」**：[task_store.py:165](backend/app/api/task_store.py#L165) 无活动阶段时的字面量回退，用户在 92-98% 进度看到「准备执行」，严重误导
5. **证据维度归属丢失**：证据回溯 Tab 的筛选 chip 全部显示「其他分析维度」（5 个相同 chip），无法按维度过滤
6. **提取字段完整性差**：日期在 URL/标题中都提取不到 → 4 维度质量门全挂 → 证据准入率 4.5% → 报告只能 G0
7. **搜索/抓取噪声与反爬**：刷题APP 内容混入证据池；bidcenter 人机验证、知乎 403 等大量抓取失败源未前置过滤

### P2 一般

8. `updated_at` 自任务创建后从不更新（进度 5%→100% 全程不变）
9. ETA 完全失真：execution API 返回 `p50=2s / p90=36s`，实际执行 4 分钟 + 暂停 35 分钟；`estimated_remaining_seconds=-1`
10. 任务日志 Tab 只有「任务已创建」1 条，durable 管线的阶段切换/关键决策未写入任务日志
11. 证据审计 Tab 显示「暂无审计数据」，与 worker 日志（`[AuditPersistence] 返回 3 条 evidence_audits`）矛盾，审计数据未贯通到前端
12. **PARTIAL 终态下「取消」按钮仍可点**：[task-execution-controls.tsx:25](frontend/src/app/components/task-execution-controls.tsx#L25) 的终态列表漏了 PARTIAL
13. 预算审计金额恒为 `0.000000 USD`（Token 定价未配置，成本不可见）
14. 「正式版本 V1 · 70 个来源」与报告实际引用 3 条证据口径不一致，易误解
15. PDF 无 ToUnicode CMap，文本无法复制/搜索

### P3 观察项

16. 计划预览的「预估耗时 5-8 分钟」准确（实际研究 ~4 分钟），值得保持
17. 澄清机制本身设计良好：阻塞分级、选项附影响说明、支持补充说明与取消——被 P0-1/2 拖累未发挥作用
18. `.env` 的 `DEFAULT_MODEL=deepseek-v4-pro` 与 DB 默认 `deepseek-v4-flash` 不一致（DB 优先），`OPENAI_API_KEY/OPENAI_BASE_URL` 为死配置，易误导运维
