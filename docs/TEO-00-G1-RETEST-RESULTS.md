# TEO-00 G1 三样本复测结论（POC v6）

## 结论

截至 2026-07-17，上海银行、邮储上海分行、中国太保的三份 `task-screening-fixture/v5` 样本均已用 DeepSeek 完成 POC v6 真实复测。**三份机器审计中的原 G1、临时推进门和最终决策仍均为 `FAIL`；业务方另行作出项目治理裁决 `MANUAL_CONDITIONAL_PASS`，仅解除后续开发和影子验证的依赖。**

v6 成功将 Schema 成功率提升为 100%，并消除了模型自行把历史采购日期标为 `active` 导致的结构失败；但 Top≤20 角色精度、跨位置集合稳定性和太保关键目标召回仍不足。人工裁决接受了当前仅有三个样本所带来的质量不确定性，以避免阻塞整体建设；该裁决不是模型质量达标结论，也不授权筛选结果影响用户任务。

### 人工条件通过裁决

- 裁决状态：`MANUAL_CONDITIONAL_PASS`。
- 裁决依据：样本数量不足，业务方接受当前质量风险以避免阻塞整体建设。
- 授权范围：继续 TEO-01、TEO-02 及后续 WBS 的开发和旁路影子验证。
- 生产边界：生产筛选默认关闭；候选筛选结果不得改写用户候选集、抓取/提取输入或最终报告。
- 审计边界：下列三份 v6 审计文件中的 `FAIL` 不删除、不覆盖、不改写；人工裁决只记录在项目文档中。
- 重新评审：完成人工标注样本达到 10 个、累计影子任务达到 50 个或自本裁决起满 30 天，任一条件先满足即按扩充数据重新评审。

## v6 协议

- 模型 / Provider：`deepseek-v4-pro` / `DeepSeek`；`temperature=0`、`thinking_mode=disabled`、SDK 与业务重试均为 0。
- Fixture 继续为 v5；POC 输出为 `task-screening-poc/v6`，不兼容 v5 模型输出。
- 模型只返回 `candidate_id`、`demand_relation`、`source_quality`、`novelty`。
- 程序从标题优先、摘要补充的原文中确定主体关系、证据形态、采购生命周期和相关性；三个视图共用一次固定 `evaluated_at`。
- 带年份的未来截止时间才可为 `active`；中标、成交、终止、废标、流标、失败等标题状态优先判为关闭；发布时间不用于推断采购有效期。
- Token 和费用继续只审计、提示，不作为质量门禁。

## 双层门禁

原 G1：关键目标及有效商机三视图 100%、采购证据组 ≥90%、角色精度 ≥80%、集合重合 ≥85%、Schema ≥99%。

临时推进门：关键目标及有效商机和 Schema 不变；采购证据组降为 ≥80%、角色精度降为 ≥70%、集合重合降为 ≥70%。即使通过，也只能获得 `development_and_shadow_only` 权限，生产默认关闭。

## 确定性规则与主要混淆

- 邮储中共识别 48 次其他分支/子公司、12 次上级主体和 48 次指定主体，邮储天津分行不再被当作上海分行或总行精确主体。
- 太保中 45 次“目标简称后接子公司限定”被降为其他分支/子公司；这消除了太保产险、寿险被直接当作集团采购的系统性错误。
- 三个样本没有任何 Schema 失败；太保仅有两次输出 Token 超过 4,000 的软提示线，均完整返回。
- 上海和邮储的主要问题是行业情报被降为无关、无关采购被抬为行业情报或目标采购；太保仍存在行业情报/无关采购被抬为目标采购的情况。
- 模型只负责需求关系后，生命周期不再成为失败来源；当前瓶颈集中在长列表中需求关系的跨位置稳定性，而不是 JSON 或日期解析。

## 实施结论

TEO-00-09 已完成，机器评测不满足 `PROVISIONAL_SHADOW_PASS`；业务方已通过 `MANUAL_CONDITIONAL_PASS` 恢复工程推进，因此：

- 不启用筛选生产开关，不改写用户候选集、抓取流程或报告。
- TEO-01、TEO-02 及后续 WBS 可继续开发；筛选能力仅允许旁路记录和比较，不得改变用户实际结果。
- 不增加自动放宽门槛、兼容解析或静默修补逻辑；机器门禁仍按 v6 原始规则计算。
- 三份 v6 `FAIL` 指标继续作为质量债务跟踪，尤其是上海最低角色精度 14.29%/集合重合 35.29%、邮储 50%/40%、太保关键目标召回 50%/角色精度 50%。
- 10 个完成人工标注样本、50 个影子任务或 30 天任一触发后，必须重新评审；生产默认启用仍需基于扩充样本取得明确质量结论。
