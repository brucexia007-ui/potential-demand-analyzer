## 3. 补丁迭代：降级条件的设计盲区（反思）

第 4 次复跑（任务 `3366e07e`）发现 B 修复未生效。根因：降级条件写的是「**准入** 0 条」，但真实世界发生的是「准入 4 条 → 渲染层（`_top_external_signals` 要求来源等级 S/A/B）把 4 条全筛掉 → 渲染 0 条」。4 条准入证据全是 UNKNOWN 等级软文章（鲸选型/新浪财经）。

**修复**：待核验线索无条件准备，附录在「渲染后为空」时兜底展示。补测试 `test_leads_render_when_render_layer_filters_all_items`（24/24 绿），第 5 次复跑验证通过。

**教训（不再犯的计划）**：降级/兜底条件必须基于用户可见的终态（渲染后），而非管线的中间状态（准入后）；写测试时必须构造「中间态非空但终态为空」的组合场景。

## 4. 实战新发现（第三轮新增）

### N8（P1，新瓶颈）：提取器 fields 超 20 项被拒，批量淘汰优质候选

5 条降级线索的被拒原因**全部**是：`模型返回的候选项非法: fields 必须为不超过 20 项的对象；已达到批量提取最小重试上限`。即：提取 LLM 对信息丰富的招标公告输出超过 20 个字段 → 契约校验拒绝 → 重试仍超 → 候选报废。**这很可能才是准入率低的隐藏主因**（不是证据不好，是提取器吃不下）。建议：fields 超限时确定性截断保留核心字段（按 must_extract 优先级）并记录截断，而非整条拒绝。

### N9（P2，设计不一致）：准入门与渲染门的可靠性口径不一致

准入（`_eligible`）不要求来源等级，渲染（`_top_external_signals`）要求 S/A/B——导致「准入 4 条、渲染 0 条」的断裂。建议：要么准入层同步可靠性要求（早失败早补检），要么渲染层放宽到 C 并显著标注「低可信来源」。

### N10（P3）：I 修复的实战验证仍缺场景

审计挂载依赖 claims 非空，claims 依赖渲染非空——在 S/A 来源为 0 的现实下，审计 Tab 依然无数据。结构上已贯通（单测钉死前端类型），实战验证需等证据质量改善或 N9 修复。
