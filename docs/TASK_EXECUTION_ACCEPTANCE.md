## 4. 生产 Go/No-Go 条件

只有同时满足以下条件，才可将本记录更新为 `GO` 并发起首次生产部署评审：

1. 如未来恢复 100 任务阶段压测，必须完整执行并保留 P50/P90/P99、队列、数据库锁、模型并发、Token、Outbox 延迟和异常审计；无未解释的任务失败、重复副作用或权限异常。当前业务方已明确跳过该阶段，因此它不作为本轮 Go/No-Go 前置条件。
2. G4 已由业务方确认；后续新增 Skill 仍须在上线前补充其最低交付口径与文案负责人。
3. 在空白正式数据库执行绿色基线，验证 ORM 零漂移、Backend 唯一迁移所有者以及 Worker/Relay 启动顺序。
4. 不将 `MANUAL_CONDITIONAL_PASS` 误表述为筛选质量门禁通过；生产筛选默认开关持续关闭，直至扩充样本后重新评审。
5. 完成首次部署演练、迁移版本确认、Relay/Worker 健康检查和无真实模型烟测，并形成书面发布决定。

执行中澄清的状态枚举和暂停语义已存在，但问题/回答持久化、等待期零外部调用以及回答后幂等恢复仍属于 v3.2 待交付闭环，不计入本轮耐久执行底座的完成能力。
